# ЛР 2 — обоснование актуальности ВКР

**Тема ВКР:** Автоматизация приёма и оформления заявок на ремонт автомобилей: импорт из внешних систем с ИИ-извлечением данных, управление согласиями на передачу персональных данных и формирование заказ-нарядов

**Автор:** Бобров Иван

**Вклад каждого участника при командной работе:** работа индивидуальная.

**Контекст:** работа выполняется на базе сервиса-площадки заявок на ремонт автомобилей pochini.online, где клиент публикует заявку, а автосервисы присылают предложения. В рамках ВКР разрабатываются три связанных модуля: (1) импорт заявок из внешних систем с ИИ-извлечением полей, (2) управление согласиями на передачу контактных данных между клиентом и сервисом, (3) формирование заказ-наряда из заявки и принятого предложения.

### Выводы по обзору

1. **Извлечение данных.** Для разбора неструктурированных заявок (сообщения, записи календаря, выгрузки 1С) LLM со структурированным выводом по схеме дают результат без обучения отдельной модели [1, 7, 9]. Для узкой области полезно разбивать извлечение на цепочку шагов [8]. Риск — галлюцинации, поэтому обязательны валидация полей (VIN, госномер, телефон, даты) и подтверждение человеком перед публикацией заявки [7].
2. **Согласия.** Согласие должно быть отдельным документом [14], информированным и без предвыбора [2], храниться в машиночитаемом виде [5], применяться как политика доступа [3] и иметь историю с возможностью отзыва [4]. Блокчейн [4] для этой задачи избыточен.
3. **Заказ-наряд.** С 01.09.2025 действуют новые Правила № 780 [15], шаблоны документов нужно сверять с ними.
4. **Нерешённые вопросы.** В найденных работах эти три задачи решаются по отдельности: извлечение — без учёта согласий, согласия — без привязки к предметной области, заказ-наряды — без автоматического приёма заявок. Сквозная цепочка «внешний источник → заявка → согласие на передачу контактов → предложение → заказ-наряд» не описана. Мало работ по LLM-извлечению на русскоязычных бытовых текстах про автомобили.

## 3. Обзор и сравнение аналогов

### Прямые аналоги

1. **1С:Альфа-Авто / 1С:Автосервис** (https://v8.1c.ru/) — отраслевые конфигурации 1С: CRM, запись, заказ-наряды, склад, зарплата. Ограничения: заявки вводятся вручную или через доработки, нет ИИ-разбора текста; требуется 1С-специалист для настройки; облачная работа и обмен с площадками заявок — через отдельные интеграции.
2. **АвтоДилер** (https://www.autodealer.ru/) — CRM для автосервиса: заказ-наряды, нормы времени, склад, проценка запчастей, интеграции с мессенджерами и телефонией. Ограничения: сведений о встроенном ИИ-разборе входящих заявок нет; согласия на ПДн не выделены в отдельный модуль с журналом.
3. **Tekmetric** (https://www.tekmetric.com/) — облачная система для автосервисов США: repair orders, оценки, цифровые осмотры, API. Ограничения: по состоянию на середину 2026 г. встроенных ИИ-функций нет, ИИ подключается через сторонние интеграции; ориентирован на рынок США, не учитывает 152-ФЗ и российские Правила № 780.

### Косвенные аналоги

1. **Uremont** (https://uremont.com/) — агрегатор: водитель оставляет заявку, сервисы присылают цены. Решает задачу приёма заявок, но не импортирует их из внешних систем сервиса и не формирует заказ-наряд.
2. **OneTrust Consent & Preferences** (https://www.onetrust.com/) — платформа управления согласиями: сбор, единый профиль согласий, синхронизация с другими системами. Ограничения: универсальная и дорогая для малого бизнеса, не связана с заявками и заказ-нарядами, ориентирована на GDPR/CCPA.
3. **Универсальные CRM с ИИ и онлайн-записью (Битрикс24, okoCRM)** — приём обращений из разных каналов, интеграция онлайн-записи с Яндекс Картами, встроенные ИИ-инструменты. Ограничения: нет отраслевой модели «автомобиль — неисправность — заказ-наряд», извлечение полей требует ручной настройки.
4. **LLM-модуль обработки заказов для TMS [7]** — та же схема «письмо → LLM → черновик → проверка», но в логистике.

### Выводы по сравнению

- **Что берём:** структуру заказ-наряда и учёта работ из 1С/АвтоДилер; открытый API и модель repair order из Tekmetric; модель «заявка → предложения от сервисов» из Uremont; принципы единого профиля и журнала согласий из OneTrust; схему «LLM → черновик → проверка человеком» из [7].

## 4. Итоги

**Итоговая тема ВКР:** Автоматизация приёма и оформления заявок на ремонт автомобилей: импорт из внешних систем с ИИ-извлечением данных, управление согласиями на передачу персональных данных и формирование заказ-нарядов

**УДК для тезиса:** 004.89

**Ключевые слова:** заявка на ремонт автомобиля, заказ-наряд, извлечение информации, большие языковые модели, структурированный вывод, интеграция информационных систем, персональные данные, согласие на обработку персональных данных, управление согласиями, автосервис.

### Актуальность исследования

1. **Изменилось законодательство.** С 01.09.2025 согласие на обработку ПДн оформляется отдельным документом [14], с 30.05.2025 действуют повышенные штрафы за нарушения при работе с ПДн (Федеральный закон от 30.11.2024 № 420-ФЗ, ст. 13.11 КоАП РФ). Площадке, которая передаёт телефон и e-mail клиента автосервису, нужен отдельный учёт согласий, а не пункт в оферте.
2. **Новые правила ремонта.** С 01.09.2025 действуют Правила № 780 [15] вместо постановления № 290, шаблоны заказ-нарядов нужно приводить в соответствие.
3. **Заявки приходят из разрозненных источников** (учётные системы сервиса, календари, мессенджеры, онлайн-запись в картах) и переносятся вручную; документооборот и работа с клиентами названы основными проблемами СТО [10, 11].
4. **Технология созрела.** LLM позволяют извлекать структурированные данные из свободного текста без обучающей выборки [1, 9], подходы для узких областей уже описаны [8], а схема с проверкой черновика человеком снижает ручной ввод [7].
5. **Готового решения нет.** Учётные системы оформляют заказ-наряды, но не разбирают входящие заявки ИИ; агрегаторы собирают заявки, но не оформляют документы; платформы согласий не связаны с предметной областью (раздел 3).

### Цель исследования

Сократить время и количество ручных операций при приёме и оформлении заявок на ремонт автомобилей за счёт разработки модулей для площадки заявок, обеспечивающих импорт заявок из внешних систем с ИИ-извлечением данных, управление согласиями на передачу персональных данных в соответствии с 152-ФЗ и автоматическое формирование заказ-нарядов.

### Задачи исследования

1. Проанализировать предметную область, источники заявок и нормативные требования (152-ФЗ, 156-ФЗ, Правила № 780).
2. Разработать модель данных заявки и схему извлекаемых полей (автомобиль, VIN, госномер, пробег, симптомы, вид работ, желаемая дата, контакты).
3. Разработать конвейер импорта: коннекторы к внешним системам → нормализация → LLM-извлечение со структурированным выводом → валидация → черновик заявки на подтверждение пользователю.
4. Разработать модуль согласий: отдельный документ с версией текста, целью и сроком; журнал событий (выдача, отзыв); выдача контактов автосервису только при действующем согласии.
5. Разработать формирование заказ-наряда (PDF) из заявки и принятого предложения по Правилам № 780.
6. Подготовить тестовый набор заявок и провести оценку: точность извлечения по полям (precision/recall/F1) в сравнении с подходом на правилах, доля заявок без ручных правок, время оформления заявки до и после.
